## 3. skill 正确性审计

### 3.1 审计方法

对 4 个详情页的原始 wikitext 逐行建立「基准台词回合」（含 `*` 台词行、选项块内所有选项/剧情值、块内续行），与脚本输出做内容级比对（按句末标点拆句后检查是否逐句出现在输出中）。

### 3.2 Bug：选项块多行内容丢失

**根因位置**：`biligame_dialogue_crawler.py` 的 `parse_options_block`（L146-170）

```python
for m in re.finditer(r"\|选项(\d+)=(.*?)(?=\||\}\}|\n)", block_text):  # L154
    options[int(m.group(1))] = m.group(2).strip()
for m in re.finditer(r"\|剧情(\d+)=(.*?)(?=\||\}\|\n)", block_text):  # L156
    plots[int(m.group(1))] = m.group(2).strip()
```

两个缺陷叠加导致丢失：

1. **正则值在第一个换行处截断**：`(.*?)(?=\||\}\}|\n)` 的 lookahead 含 `\n`。当 `|剧情N=…` 的值是**多行**时（wiki 用续行表达一个选项后的多句台词），只取到第一行。
2. **无说话人前缀的选项文本被丢弃**：`parse_speaker_line` 对无冒号的纯文本返回 `None`，调用方直接跳过，不保留。

### 3.5 修复方案（原型已验证）

重写 `parse_options_block` 为**逐行解析**：

- `|选项N=` / `|剧情N=` 值：有说话人则按台词回合收录；无说话人的**完整句子**（含句末标点 `。！？；…`）保留为 `(speaker=None, text, voiced=False)`；
- 块内**续行**（`<br>` 开头或裸行）按独立台词回合逐行解析；
- 无句末标点的纯 UI 标签（`甜甜花`、`罗莎莉亚`、`根据温迪的动作正确应答` 等）按规范规则 1（系统提示不得出现）**丢弃**；
- `|剧情N=` 空值跳过。

```python
SENTENCE_PUNCT = "。！？；…"

def has_sentence_punct(text):
    return any(c in text for c in SENTENCE_PUNCT)

def parse_options_block(block_text):
    results = []
    for raw_line in block_text.split("\n"):
        line = raw_line.strip()
        if not line or line == "{{剧情选项" or line == "}}":
            continue
        if re.match(r"^\|(选项|剧情)\d+=", line):
            value = re.sub(r"^\|(选项|剧情)\d+=", "", line).strip()
        else:
            value = line
        for seg in re.split(r"<br\s*/?>", value):
            seg = seg.strip()
            if not seg:
                continue
            parsed = parse_speaker_line(seg)
            if parsed:
                results.append(parsed)
            elif has_sentence_punct(seg):
                results.append((None, seg, False))
    return results
```

- 顺序保持原文档顺序，配音标注正确（旅行者 `voiced:false`，NPC `voiced:true`）；
- 无 UI 标签误收（`甜甜花`/`罗莎莉亚`/`根据温迪的动作正确应答` 等正确排除）。

## 4. 其他观察（非阻塞）

1. **API 限流**：核对时 MediaWiki API 多次返回 `HTTP 567`。脚本本身单页抓取正常，批量抓取大索引时建议加失败重试与退避（当前仅有 0.5s 礼貌延迟）。
2. **meta.json 节点行号**：同节内多个 `◆` 节点的 `start_line` 部分为 0（`section_offset` 按条目数累加，空节点共用前值），不影响 JSONL 正文顺序，属轻微美观问题。
